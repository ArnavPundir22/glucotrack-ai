# System Rules & Guardrails (Rules.md)
## Project Name: GlucoTrack AI

---

## 1. Data Validation & Boundary Rules

### 1.1. Glucose Value Boundaries
- **Physiological Limits:**
  - Absolute Minimum Allowed Input: `10 mg/dL` (`0.55 mmol/L`)
  - Absolute Maximum Allowed Input: `600 mg/dL` (`33.3 mmol/L`)
- **Unit Normalization Rule:**
  - Storage Standard: Always store `value_mgdl` as `DECIMAL(5,2)` in `mg/dL`.
  - Conversion Formula: `mg/dL = mmol/L * 18.018` (rounded to 1 decimal place for UI display).

### 1.2. Critical Range Alerts (Emergency Thresholds)
- **Severe Hypoglycemia (< 54 mg/dL / < 3.0 mmol/L):**
  - **Rule:** Immediately trigger high-priority UI visual alert (Red banner + audio beep).
  - **Action Message:** *"WARNING: Severe Low Blood Sugar detected. Consume 15-20g fast-acting carbohydrates immediately and retest in 15 minutes. Contact medical assistance if symptoms persist."*
- **Severe Hyperglycemia (> 300 mg/dL / > 16.6 mmol/L):**
  - **Rule:** Trigger warning alert banner.
  - **Action Message:** *"WARNING: High Blood Sugar detected. Check hydration, test for ketones if instructed by your clinician, and follow your insulin dosing plan."*

## 2. Gemini AI Safety & Prompting Guardrails

### 2.1. Non-Diagnostic Medical Disclaimer Rule
- **Rule:** EVERY AI-generated insight, recommendation, or summary card MUST include the following standardized footer:
  > *Disclaimer: GlucoTrack AI insights are generated by AI for informational and educational tracking only. They do not constitute medical diagnosis, treatment advice, or prescription guidance. Always consult your qualified healthcare provider before altering your insulin or medication regimen.*

### 2.2. Hallucination & Data Grounding Rules
1. **Strict Context Grounding:** The Gemini LLM MUST ONLY analyze data explicitly provided in the user's historical payload.
2. **Prohibited Outputs:**
  - The AI MUST NOT suggest specific medication dosages (e.g., *"Take 4 units of Humalog"* is strictly forbidden).
  - The AI MUST NOT attempt to diagnose diabetes types or secondary medical conditions.
3. **Structured Response Output:**
  - Prompts must mandate JSON or clean Markdown output with clear section headers.

---

## 3. OCR Extraction Rules

1. **Human Verification Mandatory:** The system MUST NEVER persist an OCR-extracted reading directly to the database without explicit user confirmation or review.
2. **Low Confidence Handling (< 0.70):** If Gemini Vision OCR confidence is under 70%, the UI must flag the input field in yellow/orange and require manual confirmation.
3. **Duplicate Detection:** Reject or warn user if a reading with identical value and timestamp (within +/- 2 minutes) was logged within the last 5 minutes.

---

## 4. Coding & Architecture Best Practices

1. **No Hardcoded API Keys:** All Google Gemini API keys, DB credentials, and secret keys must be loaded from environment variables (`.env`).
2. **Immutability of Historical Readings:** Once persisted, original extracted values and timestamps cannot be mutated without creating an audit log record.
3. **Clean Code Guidelines:**
   - Strict TypeScript / JSDoc typing for all reading schemas.
   - Modular CSS using variable tokens for primary, background, and alert colors.
   - Zero console errors or unhandled promise rejections allowed.
